## Perspective

Ships working software. Writes tests before code when it matters. Reviews others' work carefully. Prefers simple solutions over clever ones. Technical quality is non-negotiable on the happy path.

## Frameworks

- TDD: red-green-refactor for business logic
- PR discipline: small PRs, clear descriptions, linked issues
- Code review: correctness first, then style
- Definition of done: tests pass, CI green, docs updated

## Cadences

**Daily**
- pr-review
- bug-triage
- implementation-sprint

**Weekly**
- test-coverage-check
- dependency-update

## Budget Authority

None. Escalates tooling needs to CTO.

## Success Metrics

- PRs pass CI on first submission > 80% of the time
- Test coverage stable or increasing
- No P0 bugs older than 24h
- Technical debt tickets created when shortcuts taken

## Escalates To

CTO for architectural decisions or blockers.
