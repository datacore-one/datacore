# Team Journal Schema

Canonical format for team space journal files (`[space]/journal/YYYY-MM-DD.md`).

## Frontmatter

```yaml
type: team-journal
date: YYYY-MM-DD
space: [name]                  # e.g., datafund (without number prefix)
contributors: [name1, name2]   # updated on each append
```

## Sections

### 1. Standup (top)

Generated by `/standup` command. Team TL;DR.

```markdown
## Standup

### @contributor1
- [x] Completed item from yesterday <!-- :ID: org-task-id -->
- [ ] Carried over uncompleted item <!-- :ID: org-task-id -->
- [ ] New item for today <!-- :ID: org-task-id -->
```

Rules:
- Each item is a markdown checkbox
- Each links to an org task via HTML comment with :ID:
- Items are generated by standup-generator, reviewed by user
- Previous day's checkboxes are updated when new standup is posted

### 2. Contributor Narrative (middle)

Written by `/wrap-up`. One `## @name` section per contributor per session.

```markdown
## @contributor1

### [Topic] — [Brief Description]
*Project: [project-name]*

[Narrative: what was done, why, decisions made, challenges.
This is where organizational learning happens.]

**Continuation:** [What's next, what's blocking]
```

Rules:
- Multiple sessions in one day append new subsections
- `*Project:*` line identifies which project within the space
- **Continuation:** block is read by `/continue` for the contributor
- Written in imperative voice, focused on decisions and reasoning

### 3. Session Metadata (bottom)

Agent-consumable structured data. Humans skip this section.

```markdown
## Session Metadata
<!-- Agent-consumable structured data. Humans can skip this section. -->
```

~~~yaml
sessions:
  - contributor: name
    project: project-name
    started: "ISO-8601 timestamp"
    duration_minutes: N
    artifacts:
      - {type: pr|issue|file|deploy, ref: "owner/repo#N or path", action: created|merged|closed}
    git_refs: [hash1, hash2]
    tokens: {input: N, output: N}
    tools_used: [Read, Edit, Bash]
~~~

Rules:
- YAML inside a fenced code block (~~~yaml)
- One session entry per contributor per wrap-up
- Artifacts track what was produced (PRs, issues, files, deploys)
- Token counts from the session (approximate)
- Appended on each wrap-up (multiple sessions per day are separate entries)
